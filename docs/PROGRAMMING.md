# 编程输出

从左侧导航打开「编程输出」。画布使用 Blockly 的 Zelos 渲染器，采用 Scratch 式操作：从工具箱拖出积木，靠近凹凸接口后松开以拼接；将数值、变量、实时读数塞入圆形槽位，将条件塞入六边形槽位。循环、如果 / 否则和并行分支可以包住其他积木。

## 上手

1. 选择内置「锂电池充电」，或点「新建程序」。
2. 将动作积木接在「当点击 ▶ 运行」下面；执行顺序由连接决定，与积木在画布的位置无关。未连接的积木保留作草稿，不会执行。空槽会显示提示，并阻止启动。
3. 在「设置」里添加设备角色、启动参数和最长运行时间。每个动作及读数积木的设备下拉框均可选择角色，运行时再绑定实际电源。
4. 点击「运行」，选择在线且可写的设备，填写本次参数。程序在 Electron 主进程执行，切换页面不会停止程序。
5. 点击「停止」或侧栏「全部关闭输出」结束程序。正常完成、超时或失败也会关闭全部绑定设备输出，并通过新鲜 HR18 回读确认。

画布支持拖动空白平移、滚轮缩放、整理、居中、右键复制 / 删除、撤销 / 重做。画布位置、未连接积木和变量随程序一起保存；编辑草稿在切换页面后保留。程序库位于应用 `userData/programs.json`，支持 JSON 导入、导出和另存副本。运行记录只保存在本次应用会话中，重启后不会自动恢复输出。

## 积木

| 分类 | 功能 |
|---|---|
| 开始 | 「当点击 ▶ 运行」入口，每个程序一个 |
| 设备 | 独立调压 / 限流、增减设定、同时设定、输出开关、OVP / OCP、渐变、M1–M9 保存 / 载入、背光、清零统计 |
| 控制 | 等待、持续条件、如果 / 否则、重复 N 次、条件循环、计数循环、重复直到、一直重复、跳出 / 继续循环、并行、检查条件、结束 |
| 数据 | V / A / W、设定值、输入电压、温度、CC / CV、累计 Ah / Wh、数据组、采样速率、量程与保护阈值、参数、电池电压、日志、独立计时器 |
| 变量 | 设定、读取、增加数值变量；变量支持中文名 |
| 列表 | 清空、追加、读取、修改、删除；求长度、总和、均值、最小 / 最大、末项 |
| 运算 | 四则运算、取余、乘方、最小 / 最大、绝对值、平方根、平方、取整、对数、指数、三角函数、常数、随机数、限幅、区间映射 |
| 逻辑 | 比较、并且 / 或者 / 异或、取反、区间判断、误差比较、按条件选择数值 |
| 文字 | 文字、拼接、保留小数位、记录组合消息 |
| 自定义 | 在画布上定义和重复调用一组动作 |
| 充电 | 电池串数识别、恒压末期条件 |

共 63 种积木类型、11 个分类；下拉菜单提供多种运算及操作模式。数学函数的三角角度使用**度**。数值槽可以接条件，成立 / 不成立按 1 / 0 计算；文字仅能放入文字和日志槽，不能被当作设备设定值。无效数学结果（例如除零、负数开平方）会终止程序并关闭输出。

设备状态和 CC / CV 条件返回数字：条件成立为 1，否则为 0；CC 和 CV 条件均要求输出已开启。实时「恒流状态」数值则按设备 HR17 返回 CC = 1、CV = 0。条件槽中可使用比较积木，例如「电源 A 的输出电流 < 0.1」。持续条件等待在条件中断时立即重新计时，必须持续**超过**指定秒数且有新鲜设备样本才能继续（无设备的纯计算程序按计时检查）。累计 Ah / Wh 是设备页面中本会话的累计统计，不会在程序开始时清零。

## 多设备

一个程序最多绑定 16 台电源，条件可以引用任意绑定设备。例如，用 A 的电流决定 B 的输出，或在并行分支中分别进行两台设备的渐变输出。并行分支全部完成后才执行下一个积木；一个分支失败会取消其余分支并关闭全部输出。

纯计算、列表和日志程序可以在设置里移除全部设备角色，不连接电源也能运行；使用设备读数或动作时必须添加并绑定相应角色。

每个设备角色绑定不同设备；同一个 Core 服务的多个别名不能冒充多台设备。并行分支不能同时修改同一设备、变量、列表或计时器；占用检查也会展开自定义积木的调用关系。跨设备读数引用不受此限制。程序运行期间，绑定设备的手动设定、保护设置、预设操作、重新连接和移除均被阻止。程序之间可同时运行，但不得占用同一设备。

「同时」是对多个独立 Core 并发发起操作，各串口实际写入不保证严格同步。渐变操作最多约每 200 ms 写入一次，并等待前一次写入完成；条件和计时约每 100 ms 检查一次内存中的读数，普通判断不会增加串口轮询。

## 通用流程与示例

顶栏「示例程序」提供锂电池充电、电压阶梯扫描和双设备电压跟随。示例是可编辑的完整积木图，运行前仍需绑定设备、填写限流。

- **电压阶梯扫描**：从起始电压按步长扫描到结束电压，每次稳定 1 s 后调用「记录采样」，分别保存 V / A 列表，最后记录电流均值并关闭输出。
- **双设备跟随**：两个并行分支分别控制 A 与 B，B 每约 0.2 s 读取 A 的当前电压并按倍率跟随，用限幅积木限制到 B 的电压量程；约 10 s 后关闭两台输出。
- **取样统计**：清空列表 → 重复 N 次（将当前电流追加到列表 → 等待 0.1 s）→ 将列表均值用于比较、变量或日志。

### 循环和计时器

计数循环包含起点与可到达的终点，可设负步长倒序执行；步长不能为零，最多 100000 次。重复次数允许为 0。条件循环每轮检查当前读数；「重复直到」在条件已成立时不执行循环体。「一直重复」仍受程序最长运行时间及停止操作约束。

「跳出当前循环」和「开始下一次循环」只作用于当前分支最内层循环，不能从并行分支或自定义积木跳出调用者的循环。空循环也会让出执行时间，保证停止和断线检查能继续处理。

计时器按名称独立，未重置时从程序启动计时；重置 A 不会影响 B。计时器使用单调时间，不受系统校时影响。

### 列表

列表保存有限数值，索引从 **1** 开始，每个列表最多 **10000** 项。追加会自动创建列表，清空可重新开始采集。空列表的长度和总和为 0；对空列表取均值、极值、末项或读取越界索引会明确报错。运行面板显示每个列表的长度和最后 8 项，完整列表在本次运行内供计算使用，不跨运行保留。

### 自定义积木

打开「自定义」分类，点击「新建自定义积木」起名，将动作接进「定义」的 C 形内部，再拖出「执行 名称」接入主流程或其他自定义积木。定义本身不会自动执行；可以通过公共数值变量传入目标值、保存计算结果。支持中文名称、嵌套调用、保存和导入 / 导出，最多 32 个定义；不支持递归。重命名定义会同步修改其调用。

### 设备操作

独立调压 / 限流只写对应寄存器；连续「增加」使用本程序最近成功下发的设定值，即使下一份遥测尚未到达也能正确累加。每次仍检查设备量程。清零统计只清理桌面端本会话的 Ah / Wh / 输出时长。

切换数据组写 HR19，限 M1–M9，会载入该组 V / I / OXP；保存数据组明确写入四项参数，不自动切换。即时保护仍写 HR82/83 并改变 M0 存储。读取电池电压优先读 HR33；HR33 为零且输出关闭时，使用新读取的 HR10 端电压，不进行串数推断或打开输出。

界面状态最多约每 50 ms 推送一次，日志和最终状态立即推送；纯数学、变量、列表、计时操作不访问串口。

## 默认锂电池充电示例

示例面向普通满充电压 **4.2 V / 串**的锂电池；不适用于磷酸铁锂、4.35 V 高压锂电池或需要低压预充恢复的电池。每次启动必须输入允许的充电限流，界面不记忆上次的充电电流。

流程：

1. 关闭输出并确认。
2. 优先读取 HR32/33；HR33 为零时，使用输出关闭状态下新读取的 HR10 端电压（与界面电压相同的寄存器），并在确认弹窗和日志中标注来源。连续三次采样与确认后的复核固定使用同一来源，每次回读 HR18 确认输出关闭。按设备电压精度换算并检查稳定性。普通监控不会持续增加 HR33 轮询。
3. 以每串 3.0–4.25 V 的识别窗口列出可能串数，同时检查设备输出及 OVP 量程。总电压可能对应多个串数，例如 12.4 V 同时可能为 3S 或 4S。启动前必须核对标签、接线和串数；读数为零、无有效候选、波动超过 0.1 V 或确认期间电压变化超过 0.1 V 时，不开启输出。
4. 确认后计算 `目标电压 = 串数 × 4.2 V`，先设置限流、再设置电压。设置 `OVP = 串数 × 4.25 V`、`OCP = 限流 × 1.1`；超出设备量程时拒绝充电。**即时保护写 HR82/83，也会改变 M0 存储；不覆盖 M1–M9。**
5. 开启输出，等待 2 s 稳定。
6. 持续检查电流 `< 0.1 A`、设备为 CV 模式，且电压达到 `目标电压 − 串数 × 0.05 V`。三项连续成立超过 10 s 后关闭输出，显示「充电完成」。任何条件中断均重新计时。
7. 默认最长运行 6 小时；超时作为失败关闭输出，不显示充电完成。

连接必须让设备 HR33 或输出关闭时的 HR10 能实际读到电池电压；两者均为零时拒绝自动识别。串数仅为估算，不能代替电池标签及单体监测。多串电池需要适配的 BMS / 均衡保护，电源仅控制总电压和限流。

## 故障处理与验证范围

数据超过 1.5 s 未更新、设备只读 / 离线、OVP / OCP / OTP、输出意外关闭、写入失败、表达式无效或超时，均会终止程序并尝试关闭所有绑定设备。先等已发出的写入结束，再发关闭指令，避免停止后仍有迟到的开启指令。若无法通过回读确认关闭，界面明确列出「无法确认…已关闭输出」，需要到设备端检查。

应用正常退出时先停止程序、关闭输出，再释放 Core。设备断线、应用崩溃、系统休眠或掉电时，软件无法保证发出关闭命令；应使用设备硬件 OXP 及电池 BMS，不应依赖软件作为唯一保护。

开发验证包括：受限 AST 校验、画布与 AST 往返、连接 / 空槽规则、跨设备条件、并行取消、停止与迟到写入、持续计时重置、超时、过期数据、设备别名占用、程序库持久化；通过真实 Core + PTY 模拟器测试充电与双设备控制，并在 Electron 界面运行默认 10 s 终止流程。尚未进行真实电池充电或物理 OCP 触发验证。

以上为 0.2.0 开发阶段的历史验证范围。0.2.1 的 HR10 回退读取、遮罩层级及启动器图标修复按用户要求不运行新测试，交由人工安装与设备验收。若电池为 3.09 V 的 1S，且新鲜 HR10 在输出关闭时确实读到该值，识别候选应为 1 串、目标 4.2 V；确认弹窗会标注使用 HR10。

可使用以下模拟器体验充电流程（仅仿真）：

```bash
python3 scripts/mock-device.py --battery 3.7
# 在界面添加打印出的伪终端；模拟器 2 s 后进入约 0.05 A 的恒压阶段。
```
